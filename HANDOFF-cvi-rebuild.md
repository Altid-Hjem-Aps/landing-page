## Responsive rule (IMPORTANT — Thor wants NO fixed px)
- Use `lib/fluid.ts` → `fluid(px, minPx?, maxPx?)` returns `clamp(minRem, (px/1920)·100vw, maxRem)`. Exact px @1920, scales down, rem bounds for zoom.
- Apply via **inline style** (Tailwind can't see runtime strings): `style={{ paddingLeft: fluid(140, 32) }}`.
- Layout widths: use %, grid `fr`, flex — never px.
- Existing sections still use literal `clamp(...)` in Tailwind arbitrary values (equivalent); migrate to `fluid()` opportunistically.

5. **SavingsCounter** (`components/sections/SavingsCounter.tsx`) — reskinned: cream, green `#90ff7c` box radius 40, number up to 80px, "kr." suffix. **Two-phase animation** (`modeRef`), all derived from `liveSavings()` — nothing hard-coded: (1) **reveal** — fast slot-reel spin landing on `NEAR_END` = `FAST_END` − `COUNTUP_GAP`; (2) **bursting** — a random jump every ~2–3s that catches up to the STILL-RISING `liveSavings()` in ~`PHASE2_DURATION`(10 min), so it looks like it keeps growing. **`COUNTUP_GAP` is DERIVED**: `round(PHASE2_DURATION/BURST_EVERY × AVG_BURST)` ≈ 48 000 (10min ÷ 2.5s × 200 kr). `startBurst()`: `baseInc = (live−current) / burstsLeft` (burstsLeft = remainingTime/`BURST_EVERY`), `inc = round(baseInc × factor)` with `factor = 0.2 + rand·rand·2.4` (skewed 0.2–2.6) → **random-looking, self-correcting amounts** that always reach live at ~10 min; last burst caps to live → `modeRef='done'`. Tunables at top: `PHASE2_DURATION`, `BURST_EVERY`, `AVG_BURST` (→ gap/size), `SETTLE_MIN`/`SETTLE_RANGE` (cadence), `BURST_ROLL`, and the `factor` range in `startBurst` (amount spread). **Layout:** eyebrow 13px, heading `clamp(28,2.6vw,50)` (= FounderVideo quote), desc `16px`/lh1.8 (= FounderVideo subtext), bg `#fdfaf4` (= Hero).
